# Frontend Deployment Requirements

## What You Need (Simple Setup - No Domain/SSL Required)

### 1. AWS Account
- Free tier eligible account is fine
- You already have this since backend is deployed

### 2. AWS CLI Configured
- Already configured for backend deployment
- Same credentials work for frontend

### 3. Node.js and npm
- Already installed (you have the frontend running locally)

### 4. That's it!

## What You DON'T Need

- ❌ No custom domain required
- ❌ No SSL certificate needed
- ❌ No DNS configuration
- ❌ No Route53 setup

## How It Works

Your frontend will be accessible via:
- **CloudFront URL**: `https://d1234abcd5678.cloudfront.net` (provided by AWS, free HTTPS)
- **S3 Website URL**: `http://bucket-name.s3-website-us-east-1.amazonaws.com` (backup, HTTP only)

The CloudFront URL is auto-generated by AWS and includes free HTTPS. Perfect for personal projects!

## Quick Start

```bash
# 1. Deploy infrastructure (creates S3 + CloudFront)
cd terraform
terraform apply

# 2. Build and deploy frontend
cd ../frontend
npm run build
cd ..
aws s3 sync frontend/dist/ s3://$(cd terraform && terraform output -raw frontend_s3_bucket)/ --delete
aws cloudfront create-invalidation \
  --distribution-id $(cd terraform && terraform output -raw cloudfront_distribution_id) \
  --paths "/*"

# 3. Get your URL
cd terraform
terraform output frontend_cloudfront_url
```

## Expected Costs

**Total: ~$1-3/month** for a personal project with light usage

- S3 Storage: ~$0.10/month (for ~1GB of static files)
- S3 Requests: ~$0.50/month
- CloudFront Data Transfer: Free for first 1TB/month
- CloudFront Requests: ~$1.00/month (for 10M requests)

If you stay within AWS Free Tier (first 12 months):
- S3: First 5GB storage free
- CloudFront: First 1TB data transfer free

**Actual cost for low-traffic personal project: < $1/month**

## First Time Setup - Wait Times

- **CloudFront Distribution**: 15-20 minutes on first creation (one-time wait)
- **Subsequent Deployments**: Instant (cache invalidation takes 1-2 minutes)

## IMPORTANT: CORS Configuration

Since your frontend and backend will be on different domains, you need to ensure CORS is properly configured in your Django backend.

Your backend should already have CORS configured. Verify these settings in your Django app:

```python
# In settings.py or settings_prod.py
CORS_ALLOWED_ORIGINS = [
    "https://*.cloudfront.net",  # Allow CloudFront
]

# Or for development/testing, you can use:
CORS_ALLOW_ALL_ORIGINS = True  # Not recommended for production, but OK for personal projects
```

After deployment, update your backend's CORS settings to include your CloudFront URL.

## Troubleshooting

### Issue: Frontend can't connect to backend
**Solution**: Update CORS settings in Django to allow your CloudFront domain

### Issue: CloudFront shows old content after deployment
**Solution**: Run the invalidation command:
```bash
aws cloudfront create-invalidation \
  --distribution-id $(cd terraform && terraform output -raw cloudfront_distribution_id) \
  --paths "/*"
```

### Issue: 404 errors on React Router paths
**Solution**: Already configured! CloudFront redirects all 404s to index.html

### Issue: Mixed content warnings (HTTP/HTTPS)
**Solution**: Your CloudFront URL uses HTTPS, but your backend ALB uses HTTP. For a personal project, this is fine. Your browser will allow it.

## Optional: Add Custom Domain Later

If you want a custom domain later (e.g., `myapp.com`):
1. Register domain in Route53
2. Request SSL certificate in ACM (Certificate Manager)
3. Update CloudFront to use custom domain and certificate
4. Add Route53 DNS record

This can be done later without rebuilding everything!
